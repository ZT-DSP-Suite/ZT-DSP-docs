# 先行公开记录

> 本文件记录维护者的一项决定：**不就 ZT-DSP 协议申请专利。**

## 1. 声明

维护者不寻求、也不打算就本仓库所描述的协议技术方案在中国境内外申请专利权。

本协议以公开文档与公开实现的形式发布。公开之日本身，本协议披露的技术即成为现有技术
（《专利法》第二十二条：现有技术是指申请日以前在国内外为公众所知的技术）。

## 2. 这么做的目的

只有一个：**当有人拿专利主张本项目侵犯其专利权时，维护者与使用者有据可依。**

现行《专利法》提供两条依据：

| 条文 | 内容要点 | 作用 |
|---|---|---|
| **第六十七条** | 在专利侵权纠纷中，被控侵权人有证据证明其实施的技术属于现有技术的，不构成侵犯专利权 | 现有技术抗辩 |
| **第七十五条** | 列举不视为侵犯专利权的情形，其中第（四）项为先用权：在申请日以前已使用相同方法者，可在原有范围内继续使用 | 先用权 |

两条抗辩的共同前提是：**你能证明「我的技术在某天之前已经公开或已经在用」。**
所以公开要早，证据要留。

## 3. 首次公开时必须固化的证据

| 项 | 取法 |
|---|---|
| 公开时刻 | GitHub 服务端记录的时间；另存一份本地时间戳 |
| 提交标识 | 首次公开那个提交的完整 SHA |
| 标签 | `v1.0.0` 一类的轻量或附注标签，附注标签更好（含时间与作者） |
| 内容指纹 | 对规范正文与发布包分别取 SHA256 |
| 公开渠道 | 仓库地址、是否另发 Release、是否发布 Pages |
| 第三方存证 | 可信时间戳或公开归档（如带 DOI 的存档），可选但更硬 |

这些不是仪式。第六十七条与第七十五条都要求你**举证**，举不出来等于没有。

## 4. 本声明不表示什么

- **不影响版权**：规范正文仍以 CC BY-SA 4.0 授权，见 `LICENSE` 与 `LICENSING.md`。
- **不影响商标**：ZT-DSP 名称与标识的权利见 `TRADEMARK.md`。
- **不对第三方专利作担保**：本声明只表示维护者自己不寻求专利，不表示实施本协议不会侵犯任何第三方的专利权。使用者需自行评估。

## 5. 一个必须知道的界限

先行公开只挡**申请日在你的公开日之后**的专利。

若有人在你公开之前已经递交了相同技术的专利申请，你的公开挡不住他；那时你需要的是第六十七条的现有技术抗辩，而不是本声明。

这正说明第 3 节的证据必须从一开始就留，而不是出事再补。

## 6. 这份声明真正对应的法域

本项目点名的威胁是 US10412063B1，一件美国专利。上文引的是中国法条，而中国的现有技术抗辩不决定美国专利的有效性。真正相关的是 35 U.S.C. §102 与 §103。

- §102(a)(1)：在有效申请日之前已被专利、被印刷出版物描述或被公开使用的，不授予美国专利。它要的正是**有日期、公开、不可篡改**的发表。
- §103：公开内容还须使该发明对本领域技术人员显而易见。发表完整规范而非摘要，正是为此。
- 发表必须可被引用且有日期。PUBLICATION-RECORD.md 里的标签、提交号与哈希就是为此存在。

上文的中国法条留给中文读者作背景。两套条文都不是法律意见；一次公开能否击退某项权利要求，由律师判断。
